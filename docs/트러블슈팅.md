## T-1. 새로 받은 저장소에서 첫 가져오기가 글꼴 ERROR 를 낸다 (CI run #1)
- 증상: `scripts/verify.py` 의 가져오기 단계 실패
  ```
  ERROR: Cannot open file 'res://.godot/imported/Galmuri11-Bold.ttf-3a23d149e7b99ee54cc37134f38f9040.fontdata'.
  ERROR: Error loading custom project font 'res://assets/fonts/Galmuri11-Bold.ttf'
     at: initialize_theme (scene/theme/theme_db.cpp:84)
  ```
- 원인: 프로젝트 글꼴(`gui/theme/custom_font`)을 가져오기가 끝나기 전에 읽는다. 이 서버는 `.godot/` 가 이미 있어서 안 보였다
- 해결: `.godot/imported` 가 없으면 가져오기를 한 번 먼저 돌리고 두 번째 출력을 검사한다(`scripts/verify.py`). 확인: 이 서버에서 새로 clone 한 폴더로 verify 5/5, CI run #2 5/5

## T-2. CI 가상 화면(소프트웨어 OpenGL)이 2fps 라 화면 찍기가 30분을 넘는다 (run #1)
- 증상: `FPS_LOG fps=2 process_ms=443.5` — llvmpipe 로 1280x720 한 장에 약 0.44초, 폰 크기(2340x1080)는 더 느림. 42초(2520프레임) 자동 결투를 다 그리면 18분
- 해결: `--shots` 를 주면 찍을 프레임 바로 앞 3프레임만 그리고 나머지는 로직만 돈다(`src/main.gd` `_shots`, `RenderingServer.render_loop_enabled`). run #2 build 잡 전체 1분 40초
- 주의: 화면 찍기 모드에서는 화면 FPS 표시가 의미 없다(그리지 않는 프레임이 많다)

## T-3. run 을 취소해도 `if: always()` 단계는 끝까지 돈다 (run #1)
- 원인: GitHub 는 취소할 때 돌고 있는 단계의 `if` 를 다시 보는데, `always()` 는 참이라 취소되지 않는다
- 해결: `if: ${{ !cancelled() }}` 로 바꿨다. 이미 도는 것은 `py -3.12 tools/ci.py cancel RUN_ID --force`

## T-4. 에뮬레이터 화면이 회색 — SwiftShader(GLES 3.0)에서 3D 셰이더 링크 실패 (run #2, run #4 에서 그림은 나옴 · 너무 느림)
- 증상: `emulator` 잡은 통과(설치 · 실행 · 충돌 없음)인데 스크린샷이 회색(`docs/screenshots/P1/run2_emu_gray_swiftshader.png`). logcat:
  ```
  E godot   : ERROR: SceneShaderGLES3: Program linking failed:
  E godot   : Fragment shader active uniforms exceed GL_MAX_FRAGMENT_UNIFORM_VECTORS (261)
  I godot   : OpenGL API OpenGL ES 3.0 (OpenGL ES 3.0 SwiftShader 4.0.0.1) - Compatibility - Using Device: Google (Google Inc.) - Android Emulator OpenGL ES Translator (Google SwiftShader)
  ```
  56번(재질 변형마다). FPS 는 1 ~ 2(`process_ms` 600 ~ 800)
- 판단: Godot 4.7.2 `drivers/gles3/shaders/scene.glsl` 의 프래그먼트 기본 uniform(묶음 밖)은 100 벡터도 안 된다 — 빛 · 그림자 · 장면 값은 uniform 묶음(UBO)이다. 옛 SwiftShader GLES 가 묶음 안 값까지 세는 것으로 보인다(추정). 같은 APK 가 Mesa(CI 가상 화면, OpenGL 4.5)에서는 정상으로 그려진다 → 실기(Adreno · Mali 드라이버)는 될 것으로 본다. **확인은 폰에서**
- 다음에 해 볼 것: (1) 에뮬레이터 `-gpu swangle_indirect`(SwiftShader Vulkan + ANGLE, GLES 3 이 더 충실) (2) `scripts/emu_check.sh` 실행 전에 `adb shell settings put secure immersive_mode_confirmations confirmed`(전체 화면 안내 창이 스크린샷을 가림 — castle_M `tools/android_smoke.sh` 와 같게) (3) logcat 에 `Program linking failed` 가 있으면 점검 실패로
- 같이 볼 것: 에뮬레이터 FPS 는 소프트웨어 GPU 라 3D 판단에 못 쓴다. FPS 는 폰 화면 오른쪽 위 표시로 본다(castle_M 보류 결정 #7 · #9)
- run #4 에서 해 본 것(셋 다): (1) `-gpu swangle_indirect` → 렌더러가 `OpenGL ES 3.1 (ANGLE 2.1.17841 ...) ... Vulkan 1.3.0 (SwiftShader Device (Subzero))` 로 바뀌고 `Program linking failed` 0건, **3D 가 그려진다**(`docs/screenshots/P1/run4_emu_swangle_anr.png`) (2) 전체 화면 안내 끄기 — 안내 창 없음 (3) 링크 실패 검사 — 통과
- 남은 문제: swangle 은 swiftshader 보다 훨씬 느리다 — `FPS_LOG fps=1 process_ms=642.8 ~ 36966.9`, 150초 안에 로직 101프레임(데모는 361프레임째 시작)이라 데모까지 못 갔고, 안드로이드가 "캐슬 M 3D isn't responding" 창을 띄웠다(앱은 살아 있어 잡은 통과). 에뮬레이터는 '그려지는지 · 죽지 않는지'만 보고, 화면 · FPS 는 폰에서 본다
- 다음에 해 볼 것(필요하면): 에뮬레이터 점검만 낮은 해상도(`--resolution`)로 돌리기, ANR 창이 뜨면 `adb shell input keyevent KEYCODE_ENTER`(Wait) 로 닫기

## T-5. 칼 궤적의 투명도를 낮춰도 흰 판으로 보인다 (run #4)
- 원인: `src/view/fx3d.gd` `_process` 가 사라지게 하면서 `albedo_color.a = k`(남은 시간 비율, 1 부터)로 덮어써 처음 투명도가 무시됐다
- 1차 해결: 처음 투명도를 `_items` 다섯째 값으로 두고 `처음 투명도 × k` → run #5 에서도 **그대로 흰 판**(`docs/screenshots/P1/run5_phone_0900_floor_arc.png`). 더하기 섞기(BLEND_MODE_ADD)에서 투명도가 기대대로 먹지 않는 것으로 본다(원인 미확인)
- 2차 해결: 투명도에 기대지 않고 **색 자체를 어둡게** 한다 — 더하기 섞기에서 검정은 아무것도 더하지 않는다. 재질 색에 투명도를 미리 곱하고(`_add_mat`), 정점 색도 `Color(v, v, v, v)`, 사라질 때는 `처음 색 × k`. **run #6 에서 확인 — 얇은 반투명 띠**(`run6_phone_0420_arc_parry.png`)

## T-6. 에뮬레이터에서 앱이 시작 2초 만에 스스로 끝난다 (run #5)
- 증상: emulator 잡 실패 `앱이 살아 있지 않다 (죽었다)`. logcat:
  ```
  V Godot   : OnPause / OnStop
  V GodotActivity: Destroying GodotActivity com.godot.game.GodotApp@4f5fb5f...
  W GLThread: eglSwapBuffers failed: EGL_BAD_SURFACE
  D Godot   : Engine already initialized
  V GodotActivity: Force quitting Godot instance
  I Process : Sending signal. PID: 3346 SIG: 9
  ```
- 원인(추정): 세로 홈 화면에서 가로 고정 앱을 띄우면 화면이 돈다. 느린 에뮬레이터(시작에 몇 초)에서는 그 사이 액티비티가 다시 만들어지고, Godot 는 엔진이 이미 있으면 스스로 끝낸다. run #4 는 같은 APK 구조인데 통과 — 타이밍에 따라 난다. 이번 변경(그림만)과는 관계없다
- 해결: `scripts/emu_check.sh` 가 앱을 띄우기 전에 화면을 가로로 고정(`settings put system accelerometer_rotation 0` · `user_rotation 1`). **run #6 에서 확인 — `Force quitting` 0건, 앱 살아 있음**
- 폰: 보통은 처음부터 가로로 뜨지만, 폰 리뷰 때 "켜자마자 꺼짐"이 있으면 이 항목부터 본다
