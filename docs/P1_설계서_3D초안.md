# P1 설계서 — 3D 초안

> 정정 이력: 2026-10-26 — 첫 작성. 요구는 `docs/P1_요구사항정의서_3D초안.md`. 인터페이스 세부는 각 파일 머리 주석.

## 1. 왜 별도 디렉토리 · 별도 저장소인가 (사용자 질문 2026-10-26)
- 엔진 · 언어 · 검증이 다르다: castle_M 은 Python(pygame-ce) · pytest · 커버리지 등급, 여기는 GDScript · Godot 가져오기 · CI 내보내기. 한 저장소면 규칙(CLAUDE.md) · 검증(verify) · CI 가 섞인다
- 결과가 어느 쪽이든 깔끔하다: 3D 로 옮기면 이 저장소가 본편이 되고(pygame 이력이 바탕에 깔리지 않음), 2D 를 유지하면 이 저장소만 보관하면 된다. 같은 저장소의 브랜치라면 끝내 병합하기도 버리기도 어색하다
- 동시에 진행된다: castle_M Phase 2 리뷰 · 수정을 브랜치 전환 없이 계속할 수 있다. 세션도 폴더마다 따로라 이 폴더 세션은 작은 CLAUDE.md 만 읽는다(토큰 절약)
- 앞선 예: 「캐슬 취호전」도 형제 폴더 · 별도 저장소로 두고 스토리(`docs/story/`)만 같이 쓴다
- 대가: castle_M 데이터(기술 수치 · 외형 · 소리)를 복사해 온다 → 출처를 파일 머리에 적고, 값은 castle_M 이 먼저 바뀐다(상류 → 하류). Actions 무료 분량은 계정 단위라 저장소를 나눠도 같다

## 2. 구조와 흐름

```
입력(키보드 · 터치 src/ui/touch_ui.gd) ─┐
봇(src/combat/bot.gd, 데모 · 자동 점검) ─┼→ intent → Fighter(상태 기계) ─→ World(판정 · 역경직 · 체간 · 페이즈) ─→ 신호(events)
백도찬 AI(src/combat/boss_ai.gd) ───────┘        src/combat/fighter.gd       src/combat/world.gd                    │
                                                                                                                    ▼
                                    src/main.gd: 공격 시작 → 칼 궤적 · 소리, 신호 → 불꽃 · 빛 · 소리 · 줌 · 알림
                                    src/view/puppet3d.gd: Fighter 상태 → 관절 각도(src/view/poses.gd) → 3D 노드
```

- 로직은 `_physics_process`(60Hz 고정)에서만 돈다. 그림은 `_process` 에서 상태를 읽기만 한다 → 같은 시드면 같은 결과, 그림을 바꿔도 판정은 그대로
- 좌표: 바닥 (x, z) 미터, z 는 화면 아래(카메라 쪽). 거리 원본은 castle_M 픽셀, `src/data/moves.gd` `PX = 0.045`(키 46px ≈ 1.8m)로 바꾼다
- 결투 한 판 만들기 · 한 프레임 진행은 `src/combat/duel.gd`(게임 · 테스트 · 자동 결투가 같은 것을 쓴다)

## 3. 3D 관절 인형 (`src/view/puppet3d.gd`)
- 노드 계층: fall(뒤로 넘어짐, 발 기준) → roll(앞구르기, 허리 높이 기준) → body(돌기 · 몸집) → hips → spine → chest → neck → head, chest → 어깨 → 팔꿈치 → 손 → 칼, hips → 엉덩이 → 무릎 → 발목 → 신발. **뼈 길이 = 노드 위치**라 자세가 바뀌어도 길이가 그대로다(castle_M 2D 인형은 자세 표가 관절 위치라 위팔이 2.6 ~ 12.1px 로 변했다 — castle_M history 2026-10-26)
- 자세 = 관절 각도 표(`src/view/poses.gd`). 공격은 모양(Move.shape)마다 W(준비) · S(타격) · F(회수), 그 사이는 기술 프레임에 맞춰 이음(준비는 천천히 · 타격은 빠르게). 상태가 바뀌면 지수 감쇠로 섞는다(크로스페이드)
- 걷기 · 달리기는 주기 함수(마주 본 채 옆걸음 · 뒷걸음 포함), 발 붙이기: 가장 낮은 발목을 땅 높이로
- Skeleton3D + 스킨 메시 대신 노드 계층을 쓴 이유: 모형 파일 없이 코드로 만들고, 같은 각도 표를 나중에 GLB 뼈대(Mixamo 리그)에 옮겨 쓸 수 있다
- GLB 로 바꿀 때(FR-109): `update_from(f, dt, frozen)` 를 가진 그림 클래스 — GLB 를 불러 AnimationPlayer 동작(대기 · 걷기 · 달리기 · 베기 · 찌르기 · 차기 · 막기 · 맞음 · 쓰러짐)을 Fighter 상태 · 기술 프레임에 맞춰 고른다. 칼은 손 뼈(BoneAttachment3D)에

## 4. 화면
- Compatibility 렌더러(OpenGL ES 3): 폰 · 에뮬레이터(swiftshader) · CI 가상 화면(Mesa llvmpipe)이 같은 그림을 낸다
- 빛: 달빛(그림자) · 뒤 가로등 둘(그림자) · 앞 가로등 · 역광(그림자 없음) · 남색 환경광 · 안개 · 빛 번짐. 재질에 역광 테두리(rim)
- 카메라: 내려다보는 각 약 55도 · 화각 38도, 두 사람 사이를 따라가고 멀어지면 물러난다. 흔들림 · 결착 줌
- 화면 표시 · 터치는 기준 1280x720, 폰은 가로로 넓어진다(stretch expand)

## 5. 검증 · CI
- `scripts/verify.py`: 가져오기 → 테스트 → 자동 결투 3판(창 없음). CI `build` 잡도 같은 것을 돌린다
- CI `build`: 리눅스에 Godot 4.7.2 + 안드로이드 템플릿 → APK(arm64-v8a + x86_64) → xvfb 가상 화면에서 PC · 폰 크기 스크린샷
- CI `emulator`: API 34 x86_64 에뮬레이터에 설치 · 실행 → 첫 화면 · 데모 스크린샷, logcat 의 충돌 · 스크립트 오류, `FPS_LOG` 줄
