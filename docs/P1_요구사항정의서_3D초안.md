# P1 요구사항정의서 — 3D 초안

> 정정 이력: 2026-10-26 — 첫 작성.

## 1. 배경 (사용자 원문, 2026-10-26)
- "캐릭터 팔다리 움직이는게 너무 종잇장같아. 아래 antigravity로 개발한 건데, 확인해서 참고할 수 있는 지 알려줘. 3d로 만들어서 굉장히 더 입체적이야."
- "https://getartcraft.com/apps 이걸 활용해서 3d 게임으로 초안 만들어볼 수 있어?"
- "권장안대로 진행해. 그런데, 별도 브랜치를 따거나 별도 프로젝트 디렉토리로 만드는게 좋을까? 어느게 더 적합한지 제안해줘."

권장안(castle_M `history/2026-10-26_Claude_Phase2-입체인형검토.md` 4절): ArtCraft 는 게임 엔진이 아니라 그림 · 영상 · 3D 모형 도구 →
게임은 Godot 4 로, 첫 APK 는 임시 3D 마네킹, ArtCraft 모형은 나중에 바꿔 끼움. castle_M 의 2D 입체 관절 인형(안 1)은 이 초안 리뷰 뒤로.

## 2. 목적
castle_M Phase 2 의 결투(김신 vs 백도찬)를 3D 로 옮겨 **폰에서** 입체감 · 손맛 · FPS 를 2D 판과 비교하고,
엔진 이전(castle_M 보류 결정 #9)을 정한다. 콘텐츠를 늘리는 것이 목적이 아니다.

## 3. 기능 요구사항

| FR | 요구 | 확인 |
|---|---|---|
| FR-101 | 3D 결투 한 판 — 김신(쌍칼) 대 백도찬(사시미). 이동 · 구르기(무적) · 베기 3연타 · 돌진 찌르기 · 칼날 쳐내기 · 막기 · 체간 → 빈틈 → 제압 · 쳐낸 뒤 반격 베기 | `tests/test_combat.gd` |
| FR-102 | 백도찬 패턴과 예고 — 사시미 3연 · 스텝 베기 · 백도찬식 옆차기 · 엇박 3연(2차) · 백도찬식 찌르기(빈틈에서도, 빨간 !) · 살아있는 건 전부 죽여라(2차 · 전력) · 맞수(쳐내기) · 2차 '안경을 벗는다'. 흰 ! 쳐내기 · 빨간 ! 구르기, 판정 6프레임 전부터 커지며 깜빡임. 수치는 castle_M 과 같다 | 자동 결투(봇이 예고만 보고 받는다) |
| FR-103 | 3D 관절 인형 — 뼈 길이 고정(자세가 바뀌어도 팔다리 길이가 안 변함), 상태가 바뀌면 부드럽게 섞기, 연속 회전, 그림자 · 역광 테두리, 발이 땅에 붙음. 김신 · 백도찬 외형(정장 · 셔츠 · 넥타이 · 머리 · 안경 · 칼) | CI 스크린샷 · 폰 리뷰 |
| FR-104 | 무대 — 인천항 제3부두 밤: 달빛 · 가로등 · 역광 · 안개 · 젖은 바닥 · 컨테이너 · 계류 기둥 · 크레인 다리 · 건너편 불빛 | CI 스크린샷 |
| FR-105 | 연출 — 역경직 · 화면 흔들림 · 불꽃 · 번쩍이는 빛 · 칼 궤적 · 결착 줌 · 소리 · 음악 | CI 스크린샷 · 폰 리뷰 |
| FR-106 | 폰 — 가로 화면, 터치(따라오는 스틱 + 베기 · 쳐내기 · 구르기), FPS · 프레임 시간 표시 | 에뮬레이터 스크린샷 · 폰 리뷰 |
| FR-107 | 데모 — 첫 화면에서 6초 동안 가만히 두면 봇 대 백도찬. 누르면 직접 | 에뮬레이터 스크린샷 |
| FR-108 | 검증 — `scripts/verify.py`(가져오기 · 테스트 · 자동 결투 3판), CI(APK · 스크린샷 · 에뮬레이터 설치 · 실행 · logcat 오류 · FPS) | 테스트결과서 |
| FR-109 | GLB 로 바꿀 길 — 그림은 로직 상태를 읽기만 한다(`update_from`). ArtCraft · Mixamo GLB 캐릭터를 같은 자리에 끼운다 | 다음 단계 (사용자가 GLB 를 줄 때) |

## 4. 범위 밖 (초안이라 뺌)
난투 · 서진태 교대 · 스토리 · 대사 · 세이브 · 기술 게이지 · 카피 · 부동심 · 동요 · 점프와 쓸어 베기(파란 ^) · 손등 받기 · 엇박 찌르기(원조) · 전력 컷인 연출.

## 5. 완료 기준
- `py -3.12 scripts/verify.py` 5/5
- Actions run 성공 — APK · PC/폰 스크린샷 · 에뮬레이터(설치 · 실행 · 오류 없음 · FPS)
- 사용자가 폰에서 플레이 → castle_M 보류 결정 #9 를 "3D 로 옮긴다 / 2D 유지(안 1 진행)" 중 하나로 정한다
